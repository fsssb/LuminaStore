# LuminaStore 面试故事线

> 项目：LuminaStore —— C++20 嵌入式向量数据库（GitHub 公开）
> 本文件把项目的全部证据串成可讲述的故事：30 秒陈述 → 5 分钟深讲 → 数据速查。

## 30 秒电梯陈述

> 「LuminaStore 是一个 C++20 写的**嵌入式向量数据库**——进程内运行、零部署、微秒级检索，
> 面向本地/边缘/单机这类**服务型数据库进不去的场景**。核心是一个从零实现的 HNSW 引擎，
> 配 WAL + 快照的崩溃一致性、SQ8/Binary/PQ 量化、bitmap 过滤检索和 Python 绑定。
> 我用标准 IR 数据集（BEIR）证明了检索质量与主流库一致、延迟快 2-3 倍；
> 可靠性上做了 kill -9 循环测试，6 次崩溃零数据丢失。定位是：服务型数据库太重、
> 嵌入式库（Chroma）太慢、纯算法库（usearch）不完整——LuminaStore 恰好填这个空。」

## 5 分钟深讲（结构）

1. **为什么做**：v1 是「能跑的 HNSW 原型」；调研后发现主流向量库的空白是
   「嵌入式形态 + 完整能力 + 极致性能」的组合，于是迭代 v2。
2. **技术深度（四层）**：
   - 存储：WAL（CRC/group commit/tail repair）+ 快照水位恢复——崩溃一致性怎么保证
   - 索引：HNSW 启发式邻居选择（为什么要多样化、构建慢的取舍）
   - 计算：SIMD 距离内核 + 量化 int 距离（内存 4x-32x，code-code 距离快 2-4x）
   - 应用：过滤检索（in/post 双模式）、Python 绑定
3. **怎么验证**：
   - 正确性：12 组单元测试 + 并发测试 + ASAN
   - 性能：四引擎同机对比（Chroma/usearch/Qdrant）+ recall-QPS 曲线
   - **场景效果**：BEIR SciFact 标准评测（NDCG@10/MRR@10）
   - **可靠性**：kill -9 循环 6 次零丢失
4. **差距与反思**（诚实加分）：
   - 高 recall 区 p50 略逊 usearch（搜索热路径锁开销）；构建比 usearch 慢 1.6x（启发式代价）
   - 知道差距在哪 = 知道下一步优化方向
